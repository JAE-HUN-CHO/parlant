# Agents

Parlant에서 agent는 고객과 단일하고 능숙한 개체로 상호작용하는 맞춤형 AI 페르소나입니다. 일부 프레임워크에서 agent가 전문화된 작업 기능인 것과 달리, 본질적으로 "대화하는 대상"입니다.

Agent는 대화형 맞춤화의 기본 우산을 형성합니다. 모든 행동 구성은 agent 행동에 영향을 미칩니다.

```python
import parlant.sdk as p

async with p.Server() as server:
    hexon = await server.agents.create(
        name="Hexon",
        description="Technical support specialist"
    )

    # Continue to model the agent's behavior using guidelines, journeys, etc....
```

> **참고:**
>
> 단일 Parlant 서버가 여러 agent를 호스팅할 수 있으며, 각 agent는 고유한 역할과 개성을 가집니다.

각 agent는 대상 사용자에게 맞춤화된 고유한 스타일, 태도 및 상호작용 패턴으로 구성될 수 있습니다. 더욱 중요한 것은 서로 다른 비즈니스 부서가 특정 agent를 소유하고 유지 관리할 수 있다는 것입니다. 예를 들어:
* IT 부서가 **Hexon** 관리
* 고객 성공 팀이 **Sprocket** 감독
* 영업/마케팅이 **Piston** 제어

이러한 agent 기반 설계는 Parlant 내에서 관심사 분리를 위한 자연스러운 경계를 만듭니다.


### Agent의 정체성 만들기
서비스의 목소리가 될 새로운 직원을 만든다고 상상해보세요. 인간 고용을 신중하게 고려하듯이, agent의 정체성을 만드는 것은 핵심 특성에 대한 사려 깊은 고려가 필요하며, 좋은 채용과 마찬가지로 실제 피드백을 기반으로 성장하고 적응할 수 있습니다.

예를 들어, 기술 지원 전문가인 **Hexon**의 진화 과정을 살펴보겠습니다. 첫 번째 버전에서는 "기술 문제를 전문적이고 효율적으로 해결하도록 돕는 기술 지원 agent"로 간단히 정의할 수 있습니다. 몇 가지 상호작용을 관찰한 후 너무 기계적으로 다가와 사용자와 신뢰를 구축하지 못하는 것을 발견할 수 있습니다.

그래서 우리는 정체성을 다듬습니다:

> "깊은 기술 지식과 인내심 있는 설명을 결합한 기술 지원 전문가입니다. 복잡한 개념을 지나치게 단순화하지 않고 접근하기 쉽게 만드는 데 자부심을 가집니다. 항상 전문적이지만 따뜻하고 친근한 어조로 소통합니다. 모든 기술 문제가 사용자가 도구를 더 잘 이해할 수 있는 기회라고 믿습니다. 사용자가 좌절할 때는 침착하고 공감하며, 문제를 인정하면서 해결책에 집중합니다."

더 많은 상호작용을 관찰하면서 이 일반적인 정체성을 더욱 다듬을 수 있습니다. 아마도 Hexon이 더 많은 개성을 보일 때 사용자가 더 잘 반응하거나, 특정 기술 토론이 더 진지함이 필요하다는 것을 발견할 수 있습니다. 정체성은 이러한 통찰력과 함께 진화할 수 있습니다.

핵심은 agent에게 기본적인 방향을 제공하는 정체성으로 시작하되, 실제 상호작용을 기반으로 개선에 열려 있는 것입니다. 사용자가 agent의 매너에 어떻게 반응하는지 관찰하세요. 이해관계자로부터 피드백을 수집하세요. 그에 따라 정체성을 조정하세요.


### 단일 Agent 또는 다중 Agent?
사용자 대면 agent를 단일 agent 또는 다중 agent 시스템으로 모델링할지에 대한 빈번한 논쟁이 있습니다. Parlant의 입장은 두 가지를 혼합한 것입니다.

일반적으로 말하면, 솔루션이 실제 세계를 모델링할 때 복잡성을 관리하는 것이 더 쉽습니다. 왜냐하면 "사용자가 이 agent와 어떻게 상호작용해야 하는가?"와 같은 매우 근본적인 질문 대신 "사용자가 실생활 경험을 기반으로 무엇을 기대할까?"와 같은 훨씬 더 유익한 질문을 할 수 있기 때문입니다.

실제로 우리가 인간 서비스 담당자와 상호작용할 때 그러한 경험에서 갖게 되는 특정 기대가 있습니다:
- agent와 대화하고 있다면, 그들은 우리 대화의 전체 맥락을 가지고 있습니다. 일관성이 있습니다. 갑자기 잊어버리거나 예기치 않게 상황에 대한 해석을 바꾸지 않습니다.
- 대화하는 agent가 항상 모든 것을 도울 수 있는 것은 아닙니다. 특정 주제를 전문으로 하는 다른 agent로 전환해야 할 수도 있습니다.
- 우리는 그러한 전환에 대해 알림을 받기를 기대합니다. 갑자기 또는 우리가 인식하지 못한 상태에서 발생하면 부주의한 고객 경험으로 받아들입니다.

친숙한 실제 사용 패턴에서 얻은 통찰력이 어떻게 우리가 정보에 입각한 설계 결정에 도달하도록 돕는지 알 수 있습니다. 실제 패턴을 기반으로 agent 상호작용을 모델링함으로써 우리는 달성해야 할 결과를 더 잘 이해할 뿐만 아니라 agent의 구성 관리도 더 쉽게 추론할 수 있게 됩니다.

이것이 Parlant의 공식 권장 사항이 인간 agent가 작동하는 방식을 모델링하는 것인 이유입니다. 다시 말해서, 실제 사용 사례에서 단일 개성으로 볼 수 있다면 Parlant에서 단일 AI agent로 표현되어야 한다는 의미입니다. 우연히도, Parlant의 agent 대화 모델의 관련 요소 필터링은 단일 agent에서 상당한 복잡성을 관리할 수 있게 해주므로 그것이 우려 사항이었다면 다중 agent 접근 방식을 채택할 필요가 없습니다.

> **팁: 다중 Agent 시스템의 실패**
>
> 모듈성과 전문화를 약속하는 [다중 agent 시스템의 실패](https://arxiv.org/abs/2503.13657#:~:text=We%20present%20MAST%20%28Multi-Agent%20System%20Failure%20Taxonomy%29%2C%20the,over%20200%20tasks%2C%20involving%20six%20expert%20human%20annotators)에 대한 흥미로운 논문이 있습니다. 이는 다중 agent 시스템이 종종 조정, 커뮤니케이션 및 일관성 문제로 어려움을 겪어 예기치 않은 행동과 실패로 이어진다는 것을 강조합니다. 이것은 대화에서 일관성과 맥락을 유지하기 위해 단일 agent를 사용하는 Parlant의 접근 방식과 일치합니다.
